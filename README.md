# nanovid

Mac ネイティブの軽量な動画編集ツール。

- **トラック／レイヤー式**・**非破壊** — 元ファイルは一切書き換えない
- **中間ファイルを作らない** — 編集結果は `AVMutableComposition` とカスタムコンポジタ上にだけ存在し、実ファイルになるのは書き出しの瞬間だけ
- **テキストレイヤーはテンプレート再利用** — レイアウトをテンプレートとして持ち、インスタンス側で props（文字列・色など）を上書き。一括編集にも対応
- 入力: MP4 / MOV / WAV / MP3 / 画像　出力: MP4 (H.264 / HEVC + AAC)
- マイク録音あり・画面録画なし

## ダウンロード

### 性質テスト

`PropertySupport.swift` に種つきの乱数と縮小、プロジェクトの不変条件チェッカを置いて
ある。外部のライブラリは使わない。落ちたら操作列を 1 手ずつ削って、まだ落ちる最小の
列まで縮めて報告する。

見ているのはこのあたり。

- どんな編集操作の列を流してもプロジェクトが壊れない（start 昇順・尺が正・ID の
  重複なし・参照先がある・トラック種別と中身が合う）
- プロジェクトを変える操作は取り消し 1 回ぶんだけ戻り、やり直せる
- 書き出す範囲を切り出しても、範囲の中の見え方が変わらない
- 切り抜きで、後ろがちょうど抜いた長さだけ前へ詰まる
- 区間分割がタイムライン全体を隙間なく覆う（`InstructionPlan`）
- 保存して読み戻すと同じになる。相対パスにしても同じファイルを指す
- 目盛りのラベルが重複せず、等間隔に並ぶ（ズームの全域で）
- 吸着は結果を入れ直しても動かず、吸着先が無ければポインタに 1:1 で追従する
- ホイールの入力が消えない（縦に行き先が無ければ横へ回る）
- ハンドルの枠と、実際に描かれる位置が一致する（`MediaLayout` / `OverlayLayout`）
- 字幕は語を過不足なく順番どおりに含み、重ならない

生成器そのものの健全性も見ている。どの操作も一定回数は実際に効いていること、
下位ビットだけ違う時刻が実際に作られていること。これが無いと、全部空振りして
いてもテストは緑になる。実際に何度かそうなった。

### ヘッドレスの描画テスト

`HeadlessRender` が、プロジェクトを組み立てて `NanovidCompositor` に渡し、
1 フレームを画素として返す。再生も書き出しも通さないので速い。素材のフレームは
合成トラックごとの単色で代用する（読み込みを挟まない）。

```swift
let renderer = try await HeadlessRender.renderer(for: project)
let frame = renderer.frame(at: 1.5)
frame?.color(atX: 0.5, y: 0.5)          // キャンバス中央の色
frame?.difference(from: other)          // 2 枚の画素差の平均
```

これで背景色・フェード・重なり順・変形・不透明度と、「書き出す範囲を切り出しても
同じ絵になるか」を画素で確かめている。以前はマウス操作を合成する実機チェックを
置いていたが、実機の入力状態に引きずられて本体と関係なく落ちるので消した。

起動時にプロジェクトを開く / 動作確認用のプロジェクトを書き出す:

```sh
Nanovid --open path/to/project.nanovid
Nanovid --write-demo <出力ディレクトリ> [音声]  # デモを作って終了（音声を渡すと載せる）
Nanovid --transcribe <音声ファイル> [言語]     # 書き起こしだけ試して終了
Nanovid --inspect <プロジェクト> [時刻]       # 組み上げた合成の中身を調べて終了
```

`--inspect` はプレビューが映らないときの切り分け用。素材が見つかるか、合成トラックが
いくつできたか、命令列が途切れていないか、その時刻を 1 枚描けるかを出す。

描画から書き出しまでを GUI なしで通すテスト:

```sh
"$(xcodebuild -project Nanovid.xcodeproj -scheme Nanovid -configuration Debug \
   -showBuildSettings | awk -F' = ' '/ BUILT_PRODUCTS_DIR/{print $2}')/Nanovid.app/Contents/MacOS/Nanovid" \
   --selftest /tmp/nanovid-selftest
```

## 配布用のビルド

```sh
Scripts/release.sh
```

Release 構成でビルドし、Developer ID で署名して `dist/Nanovid-<版>.zip` を作る。
署名の内容とエンタイトルメントを出したうえで、デバッグ用の `get-task-allow` が
混ざっていれば止まる（混ざったままだと公証で弾かれる）。

Hardened Runtime を有効にしているので、マイクへのアクセスには明示のエンタイトルメントが
要る（`Nanovid.entitlements`）。これが無いと、署名したビルドだけ録音が動かなくなる。

公証（notarization）は Apple への送信になるので、スクリプトではやらない。
手順はスクリプトの最後に出る。公証しないまま配ると、受け取った側で
「開発元を確認できません」の警告が出る。

Debug はアドホック署名のまま。毎回 Developer ID で署名すると遅いのと、
デバッガを繋ぐのに `get-task-allow` が要るため。

### 描画の流れ

```
元ファイル（参照のみ）
   ↓
AVMutableComposition        ← クリップを合成トラックへ配置（トラックは使い回す）
   ↓  AVVideoComposition + NanovidInstruction（区間ごとのレイヤー一覧）
NanovidCompositor           ← Core Image で背景・映像・テキストを 1 枚に合成
   ↓
AVPlayer（プレビュー） / AVAssetWriter（書き出し）
```

プレビューと書き出しが同じコンポジタを通るので、見た目は必ず一致する。

区間の境界は、Double のままではなく **CMTime へ落としてから重複を除く**。同じ瞬間でも
計算の経路によって下位ビットがずれるため（例: フレーム境界に丸めた `88/30` と、
ひとつ前のクリップの終わり `2.1 + 25/30` は 4.4e-16 違う）。Double のまま扱って
「ほぼ 0 の区間」を捨てると命令列に隙間が空き、AVFoundation は何も描かなくなる。

### blank.mp4 について

AVFoundation のビデオコンポジションは、合成対象の映像トラックにフレームが
存在しない区間では出力を止めてしまう。テキストだけの区間やクリップ間の
ギャップでも確実にフレームを出すため、16×16 の黒素材をタイムライン全域に
敷いて土台にしている（合成レイヤーとしては使わないので画面には出ない）。
テンポラリではなくアプリ同梱のリソース。

### 座標系

レイアウトは解像度に依存しないよう、すべてキャンバスサイズに対する比で持つ。

- `Transform2D.position` — キャンバス中心を原点とした比（x は右が正、y は下が正）
- `RelFrame` — キャンバス左上を (0,0)、右下を (1,1) とするアンカー配置
- `FontSpec.relativeSize` — キャンバス高さに対する比

そのため 1920×1080 で作ったテンプレートを 1080×1920 に切り替えても崩れない。

## 字幕の自動生成

タイムラインの音声を端末内で書き起こして、字幕クリップとして並べる。
ネットワークも API キーも要らない。macOS 26 以降でのみ有効
（`SubtitleGeneration.isAvailable`。アプリ全体の対象 OS は上げていない）。

字幕タブの「自動生成」から、言語とテンプレートを選んで実行する。

```
語 70 個 → 字幕 5 枚
  00:00.00 (2.2秒) 今回はナノビドーという動画
  00:02.06 (2.0秒) 編集ツールの話をします。
  00:04.06 (3.2秒) まずはタイムラインにクリップを並べます。
  00:07.13 (2.4秒) それから字幕をつけていきます。
  00:09.25 (2.3秒) 書き出しは MP4です。
```

音声は合成済みのミックスから直接 PCM を引いて `SpeechAnalyzer` へ流す。書き起こしの
ために音声ファイルを書き出す必要がない（中間ファイルを作らない方針のまま）。

結果は新しいトラック「字幕（自動）」に入れる。既存のテロップを壊さないし、
気に入らなければトラックごと消せる。打ち直しは字幕タブの表でそのままできる。

### 区切り方

`SubtitleSegmentation` が 2 段構えで割る。文字数だけで前から詰めると、
最後に 2 文字の端数が残ったりするため。

1. **意味のまとまりに切る** — 文末（。！？）、一定以上の無音、出しっぱなしの上限
2. **長すぎるものを均等に割る** — 先に何枚に割るかを決めてから目標の文字数を出し、
   読点があればそこを優先する

合成音声のように間が無い素材でも、句読点を手がかりに文の切れ目で割れる。

## プレビュー上での配置

クリップを 1 つ選ぶと、プレビューに枠と四隅のハンドルが出る。映像・画像・テキストの
いずれも動かせる。その時刻に映っているものだけが対象。

- 枠の中をドラッグ → 移動
- 四隅をドラッグ → 拡大縮小（掴んだ隅の対角は動かない、縦横の比は保つ）

配置の計算は種類で分けてある。**コンポジタとハンドルの両方が同じものを通る**ので、
掴んだ枠と実際に映っているものがずれない。

| | 基準 | 拡大の中心 |
|---|---|---|
| `MediaLayout` | 映像・画像 | 素材の中心 |
| `OverlayLayout` | テキスト | キャンバスの中心（テンプレートのレイアウトを保つため）|

ハンドルのドラッグも、タイムラインと同じく名前付き座標空間で測る。ハンドル自身が
動くので、ジェスチャ既定のローカル空間だと位置が振動する。

## 切り抜き（範囲を抜いて詰める）

不要な区間を抜いて時間を縮める操作。カット編集の主役。

1. 抜きたいところの頭で **Q**。タイムラインに範囲が帯で出る。
2. 再生ヘッドを動かすと範囲が伸び縮みする。
3. 終わりで **W**。範囲が消えて、後ろが前へ詰まる。やめるときは **Esc**。

```
範囲 ▐███▒

前  テロップ ┌──┐ ▐███▒ ┌────┐
    映像   ┌─────███──────┐
    音声   ┌─────███──────┐

後  テロップ ┌──┐ ┌────┐
    映像   ┌─────────┐
    音声   ┌─────────┐
           ↑ すべて同じだけ縮む
```

全トラックからまとめて抜くので、ナレーションと映像のあわせがずれない
（ロックしたトラックは除く）。範囲にまたがるクリップは、かかった部分だけを
捨てて前後をつなぐ。長い素材の途中の「えーっと」を抜く使い方ができる。

## 動画の範囲（スタート位置・終了位置）

書き出す区間。既定はクリップの終わりに追従するので、何もしなければ今までどおり
先頭から最後のクリップまでが動画になる。

- 目盛りの上の青い旗をドラッグすると、開始・終了がそれぞれ動く。
  開始を動かしても終了は据え置きなので、頭を詰めたぶんだけ短くなる。
- インスペクタの「動画の範囲」で開始・長さ・終了を直接打てる（`00:04.15` 形式）。
  「自動に戻す」でクリップ追従へ戻る。
- 範囲の外は目盛りもレーンも伏せて表示する。再生ヘッドは範囲外へも動かせるが、
  再生は範囲の頭から始まり終わりで止まる。プレビューには「書き出す範囲の外です」と出す。

```
        開始 ▼                      ▼ 終了
目盛り  ▒▒▒▒│───────────────────────│▒▒▒▒▒
映像    ▒┌──┼──────┐   ┌────────┐   ├─┐▒▒▒
             ↑ここだけが書き出される
```

一度でも端を動かすと範囲は確定し、以後クリップを足しても勝手に伸びない。
範囲を伸ばしてクリップの先まで出した場合は、その先は背景色で埋める。

書き出しは `Project.croppedToOutputRange()` で範囲外のクリップを落としてから合成し、
`AVAssetWriter.startSession(atSourceTime:)` で範囲の頭を出力の 0 秒にそろえる。
範囲の先頭を 0 秒へずらした合成を組む手もあるが、`AVAssetReader.startReading()` が
-11841（不正な映像合成）で失敗する組み合わせがあるため採っていない。

端にかかるクリップを切り詰めるのは、フェードが終わったあとでだけ。`Fade` は
クリップの端からの長さしか持たないので、途中から始まるフェードを表せない。
フェードの最中で切ると、切った先から改めて 0 から立ち上がってしまい、同じ時刻でも
プレビューと書き出しで画が変わる。切らずに残しても、余分に描くのはフェードの
長さぶん（最長 5 秒）で済む。性質テスト「切り出しても範囲の中の見え方は変わらない」と、
自己テストの範囲内フレーム比較の両方で見ている。

なお書き出しのときだけ `NanovidInstruction.containsTweening` を必ず true にしている。
false のままだと AVFoundation は中身が動かない区間に 1 枚しかフレームを要求せず、
静止した区間の多い動画がフレーム数の足りないファイルになる（1 区間しか無いと尺まで狂う）。

## 複数選択でできること

矩形選択やクリック（⌘ で足し引き）で複数選んだあと、タイムラインのツールバーに
出る選択メニューから使う。

| 操作 | 内容 |
|---|---|
| まとめて移動 | ドラッグで、互いの位置関係を保ったまま動かす。先頭が 0 より手前へは出ない。段の移動は全部が移せるときだけ通る |
| 削除して詰める | 選択が占めている時間を抜き、後ろを全トラックそろえて前へ詰める |
| 隙間を詰める | トラックごとに前から詰めて隙間をなくす（先頭は動かさない）|
| 選択にズーム | 選択が画面いっぱいに入るまで寄る |
| 選択の先頭へ | 再生ヘッドを選択の頭へ |

まとめて動かしている間は、一緒に動く相手を吸着先から外している。動く相手へ
吸着すると位置関係が崩れるため。

## 画面の組み立て

目的は「切り貼り」と「字幕の編集性」なので、その 2 つに画面を寄せている。

```
┌─────────────────────────────────────────┐
│ ▣ 素材 │                      │ インスペクタ ▣ │
│ (既定で │      プレビュー        │  (畳める)     │
│  閉じる)│                      │              │
├────────┴──────────────────────┴──────────┤
│ [タイムライン] [字幕 n]  ← 下段はタブで切り替え    │
└─────────────────────────────────────────┘
```

- 左右のパネルは畳める（⌘1 / ⌘2）。素材は最初に読み込むだけなので既定では閉じている。
- 字幕の一覧・一括編集はモーダルにしない。字幕は打ちながらプレビューで確かめる
  ものなので、別ウィンドウに隠すと確認のたびに閉じることになる。
- 窓を縦に広げたぶんはプレビューへ回す（下段の高さを保持し、上段を可変にしている）。
- パネルの仕切りは自前（`PaneDivider`）。`VSplitView` / `HSplitView` は入れ子に
  すると外側のつまみが効かなくなるため使っていない。
- レイアウト編集の画面も同じ考え方。props の表は横に長いので、中央の列ではなく
  下段の横幅いっぱいに置く。中央に入れるとプレビューの幅を押しのけてはみ出す。
  脇の列は上限幅を絞ってある（`HSplitView` は空きを分け合うので、上限が緩いと
  脇が広がってプレビューが痩せる）。

仕切りのドラッグは画面全体の座標（`.global`）で測る。仕切り自身がドラッグで動くので、
既定のローカル空間だと移動量が縮んでついてこない（クリップのドラッグと同じ理由）。

## 主な操作

| 操作 | キー |
|---|---|
| 再生 / 一時停止 | Space（タイムラインにフォーカス時）/ ⌘K |
| 分割 | S / ⌘B |
| 複製 | D / ⌘D |
| 削除 | Delete / ⌘Delete |
| 1 フレーム移動 | ← → （Shift で 10 フレーム）|
| 1 秒移動 | J / L |
| ズーム | + / - 、全体を表示は F、選択に寄るのは Z |
| 切り抜き開始 / 切り抜く | Q / W（やめるのは Esc）|
| すべて選択 / 解除 | ⌘A / ⇧⌘A |
| コピー / 切り取り / 貼り付け | ⌘C / ⌘X / ⌘V |
| 取り消す / やり直す | ⌘Z / ⇧⌘Z |
| 削除して詰める | ⌥⌘Delete |
| 素材パネルの開閉 | ⌘1 |
| インスペクタの開閉 | ⌘2 |

修飾キーなしのキーはタイムラインにフォーカスがあるときだけ効く。テキスト入力中に
誤発火しないようにするため。

⌘C / ⌘X / ⌘V / ⌘A も同じくタイムライン側（`onKeyPress`）で受けていて、メニューには
載せていない。メニューに載せると項目が常に有効になり、字幕の入力欄からコピーや
全選択を奪ってしまうため。同じ理由で ⌘←→（行頭・行末）と ⌘Delete（行頭まで削除）は
使わず、素の矢印と Delete に割り当てている。

### クリップのコピーと貼り付け

コピーはクリップだけでなく、参照しているテンプレートと素材の定義も一緒に
クリップボードへ載せる。別のプロジェクトへ貼っても中身が消えないようにするため
（すでにあるものは取り込まない）。

貼り付けは再生ヘッドの位置を基準に、互いの位置関係を保って並べる。貼り付け先の
トラックは「元と同じ名前 → 選択中 → 同じ種類の最初」の順に選ぶ。

### タイムラインのマウス操作

| 操作 | 動作 |
|---|---|
| ホイール / 二本指スワイプ | パン（縦に動かす先が無ければ横へ回す）|
| ⇧ + ホイール | 横パン固定 |
| ⌘ または ⌥ + ホイール | ズーム（カーソル位置の時刻が動かない）|
| ピンチ | ズーム |
| 空きをドラッグ | 矩形選択（⇧ で選択に足す）|
| 空きをクリック | 選択を解除 |
| クリップをクリック | 選択（⌘ で足し引き）|
| クリップの本体をドラッグ | 移動（上下でトラック間も移動）。複数選んでいればまとめて動く |
| クリップの端をドラッグ | 長さを調整（素材の残り尺で頭打ち）|
| ⌥ + ドラッグ | そのあいだだけ吸着の入切を逆にする |
| 目盛りをドラッグ | シーク（尺の先へも出せる）|
| レーンを右クリック | その位置にテキスト・素材を追加 |
| 下のスクロールバー | 横スクロール |
| 右端のスクロールバー | 縦スクロール（レーンが収まっているときは出ない）|

ドラッグ中は他のクリップの端・再生ヘッド・原点に吸着する。効かないときはフレーム境界へ丸める。
吸着はタイムラインのツールバーのピンで入切できる（設定は端末ごとに覚える）。ドラッグの
最中に ⌥ を押しているあいだは、その設定と逆になる。切っていてもフレーム境界へは丸める。
フレームから外れた位置は動画として意味がないため。

再生ヘッドは置かれているクリップの末尾より先へも動かせる（末尾に足したいときのため）。
上限は `EditorStore.timelineEnd`＝描画しているタイムラインの範囲と一致させてある。
尺を超えた位置では AVPlayer が末尾のフレームに張り付いてしまうので、プレビューは
映像を隠して背景色だけにする。書き出したときと同じ「何も無い」状態になる。

スクロールは縦横とも `ScrollView` ではなく自前のオフセットで持っている。カーソル位置の
時刻を保ったままズームするには、倍率とスクロール位置を同時に決める必要があるため
（`TimelineScroll.anchoredScrollX`）。そのぶんスクロールバーも自前で描く。横は下に帯を
敷き、縦はレーンの右端へ浮かせる（行を削れないため）。

レーンの高さを数えるときは、いちばん下のレーンの隙間を足さない。足すと、ちょうど
収まる本数でも隙間ぶんだけはみ出したことになり、縦のスクロールバーが出っぱなしになる。

### タイムラインの座標系

扱う座標系は 2 つだけ。取り違えるとクリップと目盛りがずれるので、変換は必ず
`TimelineScroll` を通す（`TimelineView` 内に生の掛け算を書かない）。

| 座標系 | 定義 | 使う場所 |
|---|---|---|
| 内容座標 (content) | `x = 時刻 × pixelsPerSecond` | クリップの配置、ドロップ位置 |
| 表示座標 (viewport) | `x = 内容座標 − scrollX` | 目盛り、再生ヘッド、ポインタ位置 |

クリップのドラッグは、レーン表示領域に張った名前付き座標空間
（`TimelineView.laneSpaceName`）でポインタの**絶対位置**を測り、掴んだ瞬間のズレ
（`grabOffset`）を引いて移動先を決める（`TimelineSnap.resolve`）。

ジェスチャ既定のローカル空間で相対移動量を測ってはいけない。ドラッグ対象は
`.offset` で動くので、「ビューが動く → 測り直す → また動く」というフィードバックに
なり、クリップが左右に振動する。掴んだ基準は `value.location` ではなく
`value.startLocation` から取る（最初のイベントが届く時点でポインタは
`minimumDistance` ぶん進んでいるため）。

## プロジェクトファイル

`.nanovid` は JSON。素材はパス参照のみで、プロジェクトファイルと同じ階層以下に
あるものは相対パスで保存されるので、フォルダごと移動しても開ける。
